GT Movies Store

GT Movies Store is a movie storefront built with Django and Python, backed by a SQLite database, with the interface built on Bootstrap 5. Visitors can browse and search a catalog of movies and read reviews. Anyone can create an account, write reviews of movies they have seen, edit or delete their own reviews, and report reviews that are inappropriate. Movies can be added to a shopping cart in any quantity and purchased, and every purchase is saved to the user's order history. Site administrators manage the catalog, users, reviews and orders through the Django admin interface.

The project is organized into four Django apps: home for the landing and about pages, movies for the catalog and reviews, accounts for registration, login and order history, and cart for the shopping cart and checkout. All pages share one base template, so the navigation bar and footer stay consistent across the site.

Features and User Stories

Below are the 21 required user stories, grouped by the screen or feature that fulfills each one.

Home and About pages

As a user, I want to see information about the GT Movies Store so I can learn more about the app and its purpose.

The Home page introduces the store with a banner and welcome message, and the About page explains what the store offers. Both are reachable from the navigation bar on every page, and the footer repeats a short description of the store and contact information.

Accounts

As a user, I want to register an account so that I can access the GT Movies Store.

The Sign Up page provides a registration form asking for a username and password confirmation. It validates the input and shows a clear message for each problem — a username already in use, a password that is too short, too common, or entirely numeric — and sends the new user to the login page once the account is created.

As a registered user, I want to log in so that I can access my account data.

The Login page authenticates the username and password and starts a session. Once signed in, the navigation bar changes to show the user's name, a logout link, and a link to their orders. An incorrect username or password re-displays the form with an error message.

As a user, I want to see a list of my orders so I can track what I have purchased and my expenses.

The My Orders page lists every order the signed-in user has placed, each with its order number, date, and total paid, plus a table of the movies in that order with their prices and quantities. Movie names link back to the movie's page. The page is only reachable while logged in.

Movie catalog

As a user, I want to be able to view the list of movies available in the GT Movies Store so I can make my selections.

The Movies page displays every movie in the store as a grid of cards showing each film's cover image and title, with each card linking through to that movie's own page.

As a user, I want to search movies per title so I can make my selections.

A search box at the top of the Movies page filters the list by title. The match is partial and case-insensitive, so typing "dark" finds The Dark Knight, and the results appear in the same grid on the same page.

As a user, I want to see the details of a movie so I have the information to make my choices.

Each movie has its own movie detail page showing the title, full description, price, and a large cover image, along with the controls to add it to the cart and the reviews other users have written.

Reviews

As a user, I want to see the reviews of a movie so I can have information on whether I should purchase a movie or not.

The movie detail page lists all reviews for that movie underneath the details, each showing the author's username, the date it was posted, and the comment.

As a user, I want to create movie reviews so others can use my insights when searching for movies.

A review form at the bottom of the movie detail page lets a signed-in user post a comment, which is saved against both that movie and that user and appears in the list immediately. The form is only shown to users who are logged in, so reviews always have an identifiable author.

As a user, I want to edit my reviews so I have the freedom to change my mind about my reviews.

An Edit button appears only on reviews the signed-in user wrote, and opens an Edit Review page with the existing comment loaded for changes. The application checks that the review belongs to the user before showing the page, so one user cannot edit another user's review by guessing at the address.

As a user, I want to delete my movie reviews so I have the freedom to change my mind about my reviews.

A Delete button sits next to Edit on the user's own reviews and removes the review, returning to the movie page with the review gone. As with editing, the deletion only applies to reviews that belong to the signed-in user.

As a user, I want to report inappropriate reviews so that the comment section isn't cluttered with irrelevant/offensive reviews and the review is removed from the page moving forward.

Reviews written by other users show a Report button in place of Edit and Delete. Reporting a review removes it from the movie's page so it no longer appears for anyone. Only signed-in users can report, which keeps anonymous visitors from clearing the comment section.

Shopping cart and checkout

As a user, I want to be able to add one or more items of a movie to my shopping cart so I can purchase them in the future.

The movie detail page includes a quantity selector and an Add to Cart button, so a user can choose how many copies of that movie to buy before adding it. The cart is kept in the browser session, which means a visitor can start building a cart without an account.

As a user, I want to be able to access a shopping cart so I can list all movie items I am willing to purchase.

The Cart page, linked in the navigation bar, lists every movie added to the cart in a table with its price and quantity, and shows the running total to pay underneath. From here the user can check out with the Purchase button, which saves the order and shows a confirmation page with the new order number, then empties the cart.

As a user, I want to be able to remove all movie items from my shopping cart so I can have flexibility on what I purchase or not.

A Remove All Movies from Cart button on the Cart page empties the cart in one step. It only appears when there is something in the cart to remove.

Access and interface

As a user, I want to be able to access the GT Movies Store from any desktop using a web browser, so I can use the app anywhere with an internet connection.

GT Movies Store is a web application, so it runs entirely in the browser with nothing to install. Any desktop browser can reach every page and feature of the store over an internet connection.

As a user, I want the GT Movies Store to feature a responsive Graphical User Interface (GUI) so I can access it through different devices with diverse screen sizes.

The interface is built on the Bootstrap 5 responsive grid. The movie grid reflows from four cards per row on a desktop down to one on a phone, tables and images scale to the screen width, and the navigation bar collapses into a menu button on small screens.

Administration

As an administrator, I want to be able to manage (view, create, update, or delete) users from the GT Movies Store so we can keep information up to date.

The Django admin site gives administrators a secure, password-protected dashboard for managing user accounts — viewing the list of registered users, creating new ones, editing details and permissions, and deleting accounts.

As an administrator, I want to be able to manage (view, create, update, or delete) movies from the GT Movies Store so we can keep information up to date.

Movies are managed in the same admin dashboard, where an administrator can add a film with its title, description, price and cover image, edit it, or remove it from the store. The movie list is sorted alphabetically and has its own search box for finding a title quickly.

As an administrator, I want to be able to manage (create, update, or delete) reviews from the GT Movies Store so we can keep information up to date.

Reviews are also registered in the admin dashboard, so an administrator can create, edit, or delete any review on the site regardless of who wrote it — which is how reported or inappropriate comments are handled for good.

As an administrator, I want to be able to manage (create, update, or delete) orders from the GT Movies Store so we can keep information up to date.

Orders and the individual movie items within them are both available in the admin dashboard, letting an administrator review a customer's purchase, correct a quantity or price, or delete an order entirely.

Process

I worked through this project by following the course textbook guide, building the application one app at a time rather than all at once. I started with the project shell and the shared base template that holds the navigation bar and footer, then added the movie catalog, then user accounts and reviews, and finally the shopping cart and orders. Building in that order meant each piece had what it needed already in place. There was no point adding reviews before there were accounts to attach them to, or a cart before there were movies to put in it.

I tested as I went rather than at the end. After every major change I opened the site in the browser and clicked through the pages I had just touched, so I could see the progress and catch problems while the change was still fresh and easy to fix. That meant signing in and out to confirm the pages behaved differently for logged-in and anonymous visitors, posting and editing test reviews, and running items through the cart to checkout to make sure the totals and the resulting order came out right.

When I ran into errors or was unsure how something in Django worked, I worked through the error message first, since Django's development error pages usually point at the exact line or the missing piece. From there I used the official Django documentation, Stack Overflow, and other verified sources to understand the problem before changing anything. One change that came out of this was switching the project's database back to SQLite from MySQL as in the textbook, which removed the need to install and run a separate database server and made the project simpler to set up and run.
